Guía Técnica de Migración y Despliegue en VPS: MalagaMicro CRM

Documento técnico para migración a infraestructura propia y base de datos nueva
Importante para el desarrollador a cargo: Este documento contiene la hoja de ruta para migrar el CRM desde Lovable Cloud hacia infraestructura propia (VPS) y base de datos limpia.

Repositorio de Código Fuente:

https://github.com/Malagamicro/malagamicro.git

1. Preparación de la Infraestructura (VPS Existente)

Dado que el VPS ya está provisionado, el desarrollador deberá verificar que cuenta con el siguiente stack operativo antes de iniciar el despliegue:

  • Motor de Contenedores: Docker Engine y Docker Compose instalados.
  • Gestión de Despliegue: Coolify (o alternativa como Portainer/Traefik) para gestión de variables de entorno y certificados SSL automáticos.
  • Networking: Puertos 80 y 443 abiertos; dominio/subdominio apuntando a la IP del VPS.

2. Inicialización de la Nueva Base de Datos

El proyecto requiere abandonar la base de datos de Lovable y levantar una instancia nueva y limpia (recomendado PostgreSQL 14+ / Supabase autohosteado o en Supabase Cloud).

  • Ejecución del Esquema Inicial: El archivo SQL preparado debe ejecutarse en el siguiente orden estricto para evitar errores de Foreign Keys:
    1. Tablas base (Leads, Tareas, Presupuestos).
    2. Tablas de integración (WhatsApp, Emails).
    3. Funciones RPC y Triggers.
  • Configuración de Seguridad (RLS - Row Level Security):
    Crítico: Las políticas RLS deben re-aplicarse a la nueva base de datos. Si el desarrollador omite este paso, el frontend devolverá errores 401 Unauthorized al intentar leer/escribir datos, o peor aún, los usuarios tendrán acceso a datos cruzados.
  • Migración de Storage: Los buckets para adjuntos (facturas, fotos de perfil) deben crearse manualmente en la nueva instancia con sus respectivas políticas de acceso público/privado.

3. Configuración de Variables de Entorno (.env)

El nuevo entorno de producción requiere un .env completo. El desarrollador deberá sustituir las variables de Lovable por las de la nueva infraestructura:

VITE_SUPABASE_URL="[URL_NUEVA_BASE_DATOS]"
VITE_SUPABASE_ANON_KEY="[NUEVA_ANON_KEY]"
VITE_WAHA_API_URL="[NUEVO_ENDPONT_WAHA_CON_SSL]" # Eliminar el trycloudflare temporal
VITE_N8N_WEBHOOK_URL="[URL_N8N_PRODUCCION]"

4. Despliegue de Backend (Edge Functions)

El CRM depende de 52 Edge Functions en Deno para lógica de negocio pesada (envío de correos, comprobación IMAP, IA).

  • El desarrollador debe desplegar el directorio /supabase/functions en el nuevo entorno usando la CLI de Supabase.
  • Deben configurarse los secretos (API Keys de OpenAI, Perplexity, SMTP) de forma independiente para el runtime de las funciones.

5. Configuración de Red Externa (WhatsApp & CORS)

  • Problema de Mixed Content: Actualmente, el frontend hace llamadas directas a las APIs de WAHA/Evolution. Al subir la app web a HTTPS, los navegadores bloquearán estas llamadas si el servidor de WhatsApp no tiene un dominio con SSL válido y cabeceras CORS configuradas.
  • Solución requerida: El desarrollador deberá levantar un proxy inverso en el VPS para canalizar el tráfico de WhatsApp por HTTPS, o refactorizar el frontend para que las llamadas pasen siempre por el backend en lugar de ir directas de cliente a servidor externo.
